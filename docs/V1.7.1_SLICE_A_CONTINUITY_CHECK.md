## Scope

Slice A adds one operational endpoint:

`POST /api/v1/projects/:projectId/continuity/check`

The endpoint decides whether the current task needs `none`, `light`, or `full`
Atlas continuity. It returns a compact, typed projection and creates no
canonical record.

Slice A does not add `reconstruction/run`, compile a packet, create a receipt,
dispatch a provider, redesign the UI, add an MCP adapter, change schemas, or
change roadway, ranking, treatment, packet, or handoff rules.

## Canonical services reused

- `interpretTask` remains the canonical intent, scope, ambiguity, and roadway
  interpreter.
- `previewPacketCandidates` remains the canonical discovery, ranking,
  authority, scope, freshness, conflict, lineage-collapse, and treatment
  projection.
- The normal interpreter and preview contracts retain their existing behavior.
- Slice A adds a read-only roadway-registry mode so a continuity read cannot
  initialize or mutate the registry. A missing registry fails honestly.

## Need Gate

### `none`

Used when no bounded case, approved-mechanism, correction/conflict, or
reasoning-task dependency is likely to materially change the answer.

- No full candidate preview
- No Exact-source expansion
- No packet or provider call
- Next action: `proceed_without_atlas`

Primary reason code:

- `no_material_continuity_dependency`

### `light`

Used when a compact governed presentation preference, bounded case metadata,
or correction/conflict indicator may matter without justifying full
reconstruction.

- Reads project/case metadata and approved current mechanism projections
- Returns at most one compact governed capsule
- Does not read Exact source text
- Does not run candidate ranking
- Next action: `review_compact_continuity`

Reason codes:

- `conditional_presentation_context`
- `compact_governed_signal`
- `bounded_case_metadata`
- `correction_or_conflict_indicator`

### `full`

Used when an explicit reasoning/decision task, active-case match, or approved
mechanism match can materially affect reasoning, constraints, scope, or the
requested output.

- Calls the existing `interpretTask`
- Calls the existing `previewPacketCandidates` with the same interpretation
- Returns compact treatment counts and safety signals
- Creates no packet
- Stops on ambiguity, missing state, or unsafe budget

Reason codes:

- `reasoning_or_decision_task`
- `active_case_context_match`
- `approved_mechanism_match`

## Server ownership and isolation

- The exact top-level literal task is returned unchanged.
- Project and case records are loaded server-side.
- Client-authored case objectives, authority, eligibility, treatments,
  candidates, and canonical wording are rejected as unsupported fields.
- A case from another project returns `404` and exposes no record.
- Approved-local mechanisms require the exact supporting case.
- The endpoint follows the existing canonical read boundary and does not
  require or exercise write authorization.
- Missing read-only roadway state returns an honest failure instead of writing
  registry records.

## Compact response

The response includes:

- API version, project, optional case, and exact literal task
- Need level, reason codes, and explanation
- Primary or candidate roadways and material ambiguity
- Governing-mechanism, required-check, Consider, and audit-only counts
- Protected correction, conflict, and strongest-challenge signals
- Engine-required and Need-Gate-required current state
- Selected budget and existing preview estimates
- Records scanned, records surviving each gate, Exact sources opened,
  per-stage latency, stopping reason, and widening count
- Explicit false effects for packets, receipts, handoffs, answers, provider
  calls, authority, retrieval eligibility, and canonical mutation

The response never presents a packet, answer, seeded success, or provider
execution.

## OpenAPI

The existing V4.6 OpenAPI document retains version `4.6.0`. Slice A adds the
canonical V1.7.1 operation and typed request, response, and error schemas under
the same document without relabeling compatibility endpoints.

The request accepts only:

- `task`
- `requestedOutput`
- `caseId`
- `roadwayOverride`
- `tokenBudget` of 400, 800, or 1,600

## Parity and zero-mutation proof

For a full soccer run, Slice A and the existing canonical candidate-preview API
return the same:

- Primary roadway ID
- Scope
- Material ambiguity
- Use, Consider, and Exclude counts
- Existing engine missing-state result

Need-Gate-only current-state warnings are separately labeled rather than
silently changing treatment.

Tests compare before/after row counts across all canonical source, reasoning,
governance, roadway, live-state, packet, receipt, and handoff tables. Counts
remain identical for `none`, `light`, `full`, invalid injection, cross-project,
and missing-registry checks.
