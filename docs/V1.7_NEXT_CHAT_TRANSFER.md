# Campus Atlas V1.7 — next-chat transfer

## Mission

Campus Atlas is a governed reasoning-context continuity steward. Cody supplies
the current task. Atlas preserves consequential reasoning structure,
governance, scope, provenance, conflicts, corrections, and lineage. A
receiving model performs the final reasoning. Live sources govern current
external facts.

The product goal is not generic AI memory. It is to let consequential
experience become governed, inspectable, reversible continuity that can
materially change the bounded context supplied for a later task.

## Frozen architectural principles

1. Backend services own identity, version, scope, authority, eligibility,
   lineage, packet history, and governance history.
2. Exact source is immutable. Reconstructed and Compressed material must be
   labeled honestly.
3. One finding equals one independently governable consequence.
4. Cody’s final reviewed wording and scope govern—not Atlas’s initial draft.
5. Authority changes only through append-only governance events.
6. Route before rank: Need Gate → project/case boundary → roadway → eligible
   source families → authority/status/freshness → compact retrieval → ranking
   → Exact expansion for survivors → stop at the minimum reliable packet.
7. Discovery signals never establish authority, truth, final roadway, Use, or
   packet inclusion.
8. One primary roadway is explicit. Material ambiguity must be surfaced.
9. Use, Consider, and Exclude remain server-owned and reasoned.
10. Corrections, conflicts, strongest challenges, and required checks survive
    compression when applicable.
11. Lineage ancestors remain auditable but do not count as independent
    evidence after a governing descendant represents them.
12. Packets, packet items, receipts, handoffs, and answers are immutable
    historical snapshots.
13. Original request, Atlas packet, receiving-model answer, and receipt remain
    separate.
14. No test adapter, seed, fixture, or missing-key path may appear as
    production provider success.
15. Inspect remains the advanced console; API-first operations should be thin.

## API-first product boundary

`continuity/check` asks whether governed continuity is needed. `none` avoids
Atlas reconstruction; `light` returns bounded metadata/correction warnings;
`full` uses canonical interpretation and treatment without creating a packet.

`reconstruction/run` revalidates current state for a new key and compiles only
when full and ready. Exact retry with the same key returns the saved immutable
packet and receipt without current-state reevaluation. A new current-state
reconstruction requires a new key.

The existing four-surface Work / Atlas Found / Ask / Inspect application is
the advanced console. Do not remove it until the thin client proves parity.

## Retrieval and scaling trajectory

Semantic search finds conceptually related material when wording changes.
Keyword search preserves exact names and phrases. Graph traversal follows
relationships between people, concepts, cases, evidence, corrections,
findings, and mechanisms. Reranking judges which candidates actually answer
the current task. Evidence grading separates Exact transcript, observed facts,
approved mechanisms, summaries, Reconstructed material, and inference. Packet
compilation gives the receiving model only the smallest useful subgraph.

Atlas already contains project/case scoping, lexical/entity/relationship
discovery signals, lineage traversal, evidence/authority grading,
deterministic treatment, and bounded packet compilation.

Large-scale semantic or embedding-based retrieval is not technically
validated. GPT-5.6 cannot inherently inspect unlimited material beyond the
supplied context; retrieval must locate, grade, and provide the relevant
packet. Semantic retrieval, embeddings, vector databases, and broader graph
indexes remain research and trajectory-calibration work. They are not part of
the V1.7 acceptance claim.
