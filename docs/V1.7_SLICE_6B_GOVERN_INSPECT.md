# Campus Atlas V1.7 Slice 6B governance, structure, Inspect, and Contextual Add

Slice 6B completes the canonical stewardship and inspection surfaces around the
Slices 1–5 reasoning pipeline. It is an implementation subdivision of Slice 6
and remains governed by
[`V1.7_IMPLEMENTATION_BLUEPRINT.md`](V1.7_IMPLEMENTATION_BLUEPRINT.md).

Slice 6B does not redesign Ask, packet presentation, handoff presentation,
dogfood execution, or hosted release acceptance. Those remain Slice 6C.

## Final routes

- `/projects/:projectId/findings`
- `/projects/:projectId/findings/:findingId`
- `/projects/:projectId/conversations/:conversationId/structure`
- `/projects/:projectId/inspect`
- `/projects/:projectId/inspect/:recordType/:recordId`

The existing four-surface shell remains unchanged: Work, Atlas Found, Ask, and
Inspect. Contextual Add is a bounded shell action rather than a fifth
destination.

## Atlas Found

Atlas Found reads canonical findings only. The queue exposes:

- Needs review
- Deferred
- Awaiting outcome
- Conflict-related
- Recently resolved

Filters cover finding type, case, status, scope, and date. The default empty
state is honest and does not create a finding when a checkpoint returns zero
findings.

Finding review preserves and displays:

- Atlas's original proposal
- Cody's current reviewed wording
- The exact wording difference
- One finding type and one proposed consequence
- Scope, conditions, exclusions, uncertainty, and expected retrieval effect
- Strongest support and strongest challenge
- Exact canonical source events and message links
- Every immutable finding version
- Append-only governance history

Approve, Revise, Reject, Defer, Keep local, and Challenge continue to use the
Slice 3 governance transaction. The interface waits for the server response,
then displays the governance event ID, prior/new authority, prior/new scope,
and exact retrieval effect before refreshing the canonical finding.

Deferral requires a return condition or review date and has no authoritative
retrieval effect. Rejection visibly preserves source and proposal history,
removes eligibility, suppresses an unchanged proposal hash, and allows only a
materially changed later proposal. Rollback uses the existing canonical
rollback service, creates a new governance event, restores prior eligible
state, and does not mutate packet or handoff history.

Supersede and Retire are not exposed as frontend-only actions because the
current canonical finding service does not yet support those mutations.

## Structure

The conversation workspace links to a project-scoped Structure route. It reads
the same canonical conversation, case, event, reasoning, finding, governance,
packet, and boundary records available through the API.

Structure progressively exposes:

- Stable case core
- Meaningful events
- Reasoning nodes, evidence, and challenges
- Mechanism candidates
- Outcome and postmortem
- Governance history
- Packet influence history
- Boundary proposals and operations
- Unassigned and chat-only events

Attach, move, unassign, and chat-only changes create an explicit boundary
proposal and apply it only after the user submits the action. They retain the
existing reversible operation history. Split and merge stop at a proposal and
are never silently applied. Eligible reversals append a reversal operation and
restore the prior assignment or case state.

Exact-source links preserve canonical IDs and URL-encode them only at route and
fragment construction.

## Reasoning-node correction

Slice 6B adds:

- `POST /api/v1/projects/:projectId/reasoning-nodes/:nodeId/corrections`

The mutation:

1. Enforces project ownership and centralized write authorization.
2. Requires the current source version.
3. Rejects a stale source version.
4. Requires an idempotency key.
5. Preserves the prior reasoning-node version.
6. Appends a `Reconstructed` corrected version.
7. Updates only the stable node's current-version pointer.
8. Appends a governance event with action `correct`.
9. Preserves authority, scope, and status.
10. Returns `wording_corrected_no_authority_promotion`.

A correction does not become a mechanism, principle, or project-wide
authority. The existing append-only D1 triggers continue to protect reasoning
node versions and governance events.

## Inspect

Slice 6B replaces the Slice 6A placeholder with readable canonical tabs:

- Cases
- Reasoning
- Mechanisms
- Principles
- Blueprint
- Packets

Advanced views expose:

- Governance
- Roadways
- Live state
- Evaluations
- Localized relationships
- Handoffs

Cases show objective, status, current thesis and decision, constraints,
outcome/postmortem state, pending findings, change time, and packet influence.
Case detail exposes linked conversations, events, nodes, checkpoints, findings,
governance, packet use, and boundary history.

Reasoning detail shows exact source lineage, every immutable version, related
events/findings/mechanisms, packet influence, and correction history.

Mechanism detail shows the stable ID, immutable versions, local/project scope,
authority, status, supporting cases/nodes, strongest challenges, governance,
and packet usage. Approved mechanisms are described as scoped authority rather
than universal truth. A mechanism derived from a reconstructed import carries
the historical-source limitation.

Principles remain honestly empty because V1.7 currently has no stable canonical
principle record or governed promotion service. A `principle_proposal` finding
is not presented as an approved principle.

Blueprint displays the frozen method, canonical roadway definitions, and any
project-scoped Blueprint revision findings separately. It does not silently
edit the frozen authority.

Packets read the immutable Slice 4 packet and receipt. Inspect never recompiles
a historical packet.

## Contextual Add

The shell provides the bounded Contextual Add flow for:

- Case
- Research or evidence
- Outcome
- Correction
- Challenge
- Observation
- Proposed connection

The canonical endpoint is:

- `POST /api/v1/projects/:projectId/contextual-add`

It requires centralized write authorization and an idempotency key. Cases map
to the existing `cases` and optional `conversation_case_links` records.
Research/evidence, outcomes, corrections, challenges, observations, and
proposed connections map to canonical `events`. No second ontology or client
authority model is introduced.

Contextual event captures default to `Reconstructed`. An `Exact`
representation is accepted only when the submitted content matches a canonical
message span. Proposed connections remain observed events with a proposed,
non-authoritative relationship in metadata; they do not create an authoritative
edge. Outcomes update the selected canonical case's outcome state but do not
create a mechanism.

Every successful capture returns a connection receipt containing:

- Canonical record ID
- Destination
- Project, optional case, and conversation
- Record type
- Representation
- Authority
- Source
- Suggested relationships
- Next action
- Whether retrieval changed
- Why retrieval did or did not change

Most receipts state that retrieval did not change because no consequential
meaning was approved.

## Project isolation and session behavior

All reads and writes include the canonical project ID and verify ownership in
D1. Direct links to another project's finding, case, reasoning node,
conversation structure, mechanism, packet, or capture fail instead of showing
similar content.

The Slice 6A in-memory write session is reused. Slice 6B does not add
per-screen keys, browser storage, rendered secrets, or logs containing the key.
Read-only users can inspect canonical records. Unauthorized mutations fail
visibly and leave canonical state unchanged.

Project switching changes the route and remounts the project-scoped tree.
Selected records, Structure state, governance results, Contextual Add drafts,
and detail views from the prior project are not retained.

## Empty and failure states

Slice 6B explicitly represents:

- Nothing consequential awaiting governance
- No deferred finding matching a filter
- No approved principles
- No packets
- No governance history
- No localized relationship
- No associated case
- Finding or Inspect record unavailable
- Governance failure
- Stale current version
- Project access denied
- Structure mutation failure
- Non-reversible boundary operation
- Node-correction version conflict
- Contextual Add failure
- Canonical D1 unavailable
- Unauthorized write

Failures state what remains valid and do not substitute fixtures, seeded
content, or local reconstructed success.
