# V1.7 Dogfood — Lineage-Protected Packet Boundary

## Status

This narrow dogfood fix separates a record's historical protected role from
its eligibility to enter a reconstruction packet. V1.7 remains not
release-accepted, packet compilation remains paused, and the API-first
architecture spike remains queued.

## Root cause

Stage 2 correctly collapsed the approved mechanism's finding, reasoning nodes,
and Exact events into excluded lineage. Packet minimum-safety logic still
selected every record with a protected role, however, and the handoff receipt
reported every correction-role record as supplied. That allowed an excluded
Exact correction event and correction node to cross the Stage 2 treatment
boundary.

## Canonical boundary

`worker/packet-eligibility.ts` owns the shared server rule. Protected packet
content must be `Use` or `Consider`, must not be lineage-only, terminal, stale,
or superseded, and must retain a materially relevant protected role.

Excluded lineage ancestors still preserve:

- canonical source and version IDs;
- representation, scope, authority, freshness, and treatment reason;
- lineage-only and represented-by metadata in the immutable receipt snapshot;
- an `Exclude` packet item for inspection and audit.

They do not enter packet prose, minimum-safe sizing, protected-correction
counts, unchanged-protected UI lists, or handoff claims about supplied
corrections. Independent `Consider` corrections, protected challenges,
unresolved conflicts, and required live state retain their existing safety
behavior.

## Native dogfood verification

The existing Sports Engine run was interpreted and previewed once, then moved
to Stage 3 without compiling:

- state: `ready`;
- `Use`: 1 approved-local mechanism;
- `Consider`: 0;
- excluded/lineage-only: 5;
- required checks: 5;
- packet-eligible protected corrections: 0;
- estimated safe minimum: 278 tokens;
- estimated final size: 278 tokens;
- packets: 0;
- handoffs: 0.

The complete Cody-reviewed mechanism remains the sole governing context. The
five ancestors remain inspectable for audit, and no authority or governance
state changed.
